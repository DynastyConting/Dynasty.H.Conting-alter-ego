# 通用归因候选生成标准 V0.2

**状态：候选架构，尚未最终冻结。**

**所属：七步法第 4 步「归因」的原生工具候选版本。**

## 1. 目标

在不依赖执行者临时灵感的情况下，系统生成、筛选和描述候选原因。

目标不是保证一次找到真正根因，而是：

- 降低漏因；
- 降低凭空编因；
- 允许 UNKNOWN；
- 允许 NOT APPLICABLE；
- 允许分类体系承认自己有缺口；
- 为下一动作提供一个可继续验证的候选原因集合。

## 2. 分类单位：最小因果陈述（Minimal Causal Statement）

不再给整起复杂事故强行分配一个唯一类别。

基本记录形式：

> **因素 X，在条件 C 下，通过机制 M，使结果 Y 更可能发生、发生得更严重，或更难恢复。**

复杂事件应拆成多条候选因果记录，再表达它们之间的组合关系。

## 3. 十二个归因搜索域（Attribution Search Domain）

这些是归因搜索域，不是“宇宙只有十二种根本原因”的宣言。

### 01 流、供给与暴露

检查实际进入、离开或作用于系统的东西：可用性、中断、身份 / 成分 / 污染、数量、速率、浓度、波动、实际暴露。

核心问题：**实际流入、流出或暴露了什么？多少？以什么方式？**

### 02 状态、完整性与能力

检查对象当前本体状态：故障、损伤、退化、状态异常、性能不足、当前能力不满足要求。

### 03 目标、规格、结构设计与固有权衡

检查系统是否从目标、需求、结构、架构或固有权衡上就存在问题。

允许返回 NOT APPLICABLE（不适用）。某些自然 / 生理问题并不存在有意义的“设计者”。

### 04 执行与流程

检查动作是否正确发生：遗漏、错误执行、多做、越权、步骤错误、方法 / 流程不适配。

### 05 时空协调

检查时间与空间：顺序、同步、并发、时机、持续时间、频率、速率、位置、对准、路径、布局、拓扑。

### 06 接口、依赖与传播

检查事物之间的连接关系：接口契约、兼容性、共享依赖、共因失效（Common-Cause Failure）、干扰、耦合、级联、涌现交互。

### 07 资源、容量、分配与韧性

检查系统可以调用的东西是否足够：总量、容量、瓶颈、争用、分配、余量、冗余、替代、恢复资源。

**与 01 的区别：**

- 01 更偏“实际流了多少”；
- 07 更偏“有没有能力提供 / 承载足够的东西”。

例如：

- 周围有水但不喝：可命中 01，07 未必异常；
- 根本没有足够水：07 异常，并可能进一步导致 01 的低流入；
- 水源中断但库存仍能维持：07 / 韧性已异常，当前 01 仍可能正常。

### 08 信息、测量与模型

检查信息生命周期：缺失、陈旧、不可访问、测量错误、分类错误、语义 / 传递失真、模型 / 假设 / 表征错误。

注意：系统内部信息问题 ≠ 调查者自己证据不足。

### 09 控制、屏障与恢复

检查异常为何没有被发现、阻止、隔离或恢复：检测、诊断、控制逻辑、纠偏、防护、隔离、缓解、恢复。

### 10 变化、积累与生命周期

检查长期演化或状态转换：磨损、债务积累、路径依赖、配置漂移、数据漂移、习惯形成、版本偏斜、升级、迁移、维护、退役转换。

**待继续审查：未来可能部分降为动态属性轴。**

### 11 激励、适应与选择

检查主体 / 系统对环境和规则的适应性响应：KPI、道德风险、逆向选择、协调困境、合法博弈、规则利用、市场 / 行为 / 生物适应与选择。

**适应不等于恶意。**

### 12 随机实现与不可约变异

检查是否不存在可识别错误，只是概率风险被实现：正常随机波动、低概率风险实现、个体差异、不可约随机性。

必须区分：

- **随机不确定性（Aleatory Uncertainty）**：世界本身具有概率性；
- **认知不确定性（Epistemic Uncertainty）**：只是我们不知道。

**待继续审查：未来可能转化为概率属性轴。**

## 4. 每个搜索域的合法结果

- **NOT APPLICABLE**：不适用；
- **NO FINDING**：适用且已经检查，目前未发现异常；
- **UNKNOWN**：未知 / 当前信息不足；
- **POSSIBLE**：存在合理候选；
- **SUPPORTED**：已有事实支持；
- **CONTRADICTED**：当前事实与候选冲突；
- **EXCLUDED**：已有足够证据排除。

**NOT APPLICABLE 与 NO FINDING 必须分开。**

## 5. 五组正交标签

候选因素生成后，再用独立字段描述，而不是继续逼它抢一个唯一“大类身份证”。

### A. 因果角色（Causal Role）

触发；脆弱性 / 前置条件；传播 / 放大；预防屏障失败；检测失败；隔离失败；恢复失败；贡献因素等。

### B. 所在层级（System Locus）

边界输入；部件 / 个体；接口 / 网络；流程 / 控制；团队 / 组织 / 制度 / 市场；外部环境；跨层系统等。

### C. 生命周期来源（Lifecycle Origin）

目标 / 需求；设计；实现 / 制造 / 采购；部署 / 运行；维护 / 变更 / 迁移；退役 / 恢复等。

### D. 能动性与意图（Agency and Intent）

无主体自然过程；无意错误；已知风险未处置；合法策略适应；规则博弈 / 违规；欺骗 / 舞弊；敌对攻击 / 破坏；未知。

### E. 证据状态（Evidential Status）

已确认；很可能；可能；存在争议；证据不足；竞争假设未决；个案不可判定；已排除；测量假象等。

## 6. 开放出口

### 分类体系缺口（Taxonomy Gap）

原因已经识别，能够写出明确因果陈述，但现有搜索域无法合理容纳。

必须保留自由文本，并进入后续分类体系修订。

### 原因未决（Cause Unresolved）

当前尚不能识别具体原因，可继续细分为：

- 尚未调查；
- 关键证据缺失；
- 多个竞争假设无法区分；
- 个案归因不可判定。

“我不知道该选 02 还是 07”不是未知，那是分类规则有歧义。

## 7. 压力测试规则

以后每个搜索域至少问三个问题：

1. **它有没有产生新的候选机制？**
2. **这个候选是不是其他域已经完整生成过？**
3. **区分这个域以后，会不会导致不同的验证方法或下一动作？**

两个域同时命中不自动意味着应该合并。若它们描述因果链上两个对理解或行动有意义的不同位置，就有独立保留价值。
