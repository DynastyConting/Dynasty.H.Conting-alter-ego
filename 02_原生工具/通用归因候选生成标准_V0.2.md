# 通用归因候选生成标准 V0.2

**状态：候选架构，尚未最终冻结。**

**所属：七步法第 4 步「归因」的原生工具候选版本。**

**2026-09-01 V-005 修订状态：** 搜索域 01—03 主体结构暂时冻结；04—12 仍待逐域审查。文件名继续保留 V0.2，不因局部修订假装整个工具已经完成新版本。

## 1. 当前功能定位

第四步不再要求执行者直接猜出“真正原因”。它的黑箱接口进一步收窄为：

> **输入一个已经由前三步形成的 Problem Representation（问题表征），输出若干值得继续探索的 Candidate Direction（候选探索方向）。**

目标是：

- 系统扫描可能值得继续查的方向，降低明显漏项；
- 不因执行者临场能力不足而完全卡死；
- 不把缺失信息偷偷补成确定结论；
- 允许 UNKNOWN（未知）与 NOT APPLICABLE（不适用）；
- 不在第四步直接生成最终解决方案或具体行动。

第四步产生的方向交给第五步继续转化为 Probe（探测）、Intervention（干预）、Experiment / Trial（实验／试错）或其他下一动作候选。

## 2. 输入边界与候选因果陈述

第四步读取前三步已经形成的问题表征，不重新执行事实采样。

当搜索方向进一步发展为较具体的因果候选时，可以使用 Minimal Causal Statement（最小因果陈述）记录：

> **因素 X，在条件 C 下，通过机制 M，使结果 Y 更可能发生、发生得更严重，或更难恢复。**

但这不是每个初始扫描命中的强制格式。一个搜索域可以先只返回“值得继续查的方向”，不能为了填满因果句而凭空制造机制。

## 3. 通用审查状态

所有搜索域与其下级检查项统一使用四值状态：

- **NORMAL（正常）**：当前符合预期或未发现有意义偏差；
- **ABNORMAL（异常）**：已经发现值得继续探索的偏离；
- **UNKNOWN（未知）**：该项理论上需要判断，但当前信息不足；
- **NOT APPLICABLE / N/A（不适用）**：该项对当前问题没有意义。

边界：

- ABNORMAL 只表示“存在偏离”，不编码严重程度；
- “不知道”不能洗成 NORMAL；
- 没有明确判据时，不允许用“够不够”“好不好”“精力足不足”等模糊语言凭感觉判 ABNORMAL；
- POSSIBLE / SUPPORTED / CONTRADICTED / EXCLUDED 等若仍需要使用，应归入后续候选的 Evidential Status（证据状态），不再与域级审查状态混在一层。

## 4. 十二个搜索域（Search Domains）

这些是搜索方向，不是“宇宙只有十二种原因”的宣言。一个问题可以同时命中多个域，也可以对某些域返回 N/A。

### 01 Input & Exposure（输入与暴露）

采用 Two-pass Scan（双遍扫描）。

#### A. Normal Input Audit（正常输入审查）

检查系统本来应该接受的输入：

1. **Input Identity（输入对象身份）**：实际进入的是不是应进入的对象类别。只看对象身份，不把同类对象的规格差异硬算成身份变化。
2. **Input Source（输入来源）**：输入对象本身来自哪里、来源是否正常。它与第二步 Information Provenance（信息来源／信息溯源）严格区分：第二步问“我怎么知道”，本项问“这个输入对象从哪里来”。
3. **Quantity（数量）**：总量、个数、体积、金额等是否偏多或偏少。
4. **Quality（质量）**：规格、等级、纯度、完整性、性能等是否符合要求。同一对象类别内的型号、规格差异优先在这里审查。
5. **Rate（速率）**：单位时间输入是否过快、过慢或波动异常。
6. **Timing（时序）**：是否存在过早、过晚、顺序、频率、间隔、持续时间或同步异常。
7. **Place（位置）**：输入是否进入正确地点、部位、系统节点、账户或分配位置。
8. **Entry Mode（进入方式）**：输入通过何种通道、接口、形式或路径进入，进入方式本身是否异常。

#### B. Exposure Audit（暴露审查）

第二遍单独检查：

> **除预期输入之外，系统是否额外接触、接受或受到本不应存在的因素作用？**

发现 Exposure Object（暴露对象）后，可以对该对象重新套用 Input Identity / Input Source / Quantity / Quality / Rate / Timing / Place / Entry Mode 八项审查。

本域只输出输入／暴露方面的异常或关键未知，不直接宣布最终原因。

### 02 State, Integrity & Task Capability（运行状态、完整性与任务胜任能力）

#### A. Operational State（运行状态）

与第三步 Structuring（结构化）中的 Current State（当前状态）区分：

- **Current State（当前状态）**负责描述“现在是什么样”；
- **Operational State（运行状态）**负责审查“当前运行状态是否构成值得继续探索的异常或未知方向”。

检查四项：

1. **Operating Mode（运行模式）**：正常、降级、安全、维护、手动／自动等模式是否适合当前任务；
2. **Activation State（激活状态）**：应启用、在线、接合或工作的部分是否已激活；
3. **Load State（负载状态）**：系统当前承受的负载是否处于允许范围。与 01 的 Rate（输入速率）区分：Rate 看输入进得多快，Load State 看系统当前被压到什么状态；
4. **Readiness State（就绪状态）**：初始化、校准、预热、必要准备等有明确条件的前置状态是否满足。不存在明确标准时不得用“是否准备充分”等空气词机械判定。

#### B. Integrity（完整性）

完整性只检查当前本体是否保持正常结构与原有功能：

1. **Structural Integrity（结构完整性）**：组成、形态、尺寸、位置和结构关系是否偏离正常结构。异常可包括缺失、断裂、变形、移位、异常增生、多余结构或错误组装；
2. **Connection Integrity（连接完整性）**：本应连接、连续或互通的部分是否出现断开、松脱、错接、堵塞或不当连通；
3. **Functional Integrity（功能完整性）**：组成部分仍存在且结构关系保持时，其原有功能是否仍正常存在。

**Degradation（退化）与 Fatigue（疲劳）暂从 Integrity 摘出。** Wear（磨损）、Aging（老化）、Recovery（恢复）等时间过程留待搜索域 10 的动态变化／生命周期审查。

#### C. Task Capability（任务胜任能力）

对象自身可以完全正常，却仍可能无法完成当前具体任务。

因此只问：

> **对象现有能力范围是否达到当前任务的明确要求或阈值？**

没有可识别任务标准时，不允许凭感觉判“不胜任”，应返回 UNKNOWN 或 N/A。

### 03 Requirements, Design & Trade-offs（要求、设计与固有权衡）

原“目标、规格、结构设计与固有权衡”重构为三个互相区分的检查项。

Goal（目标）不在本域重新审问，因为第一步 Boundary Setting（定界）已经记录目标状态与 Subjective Exchange Willingness（主观交换意愿）；第三步 Structuring（结构化）的原生工具继续记录 Constraints（客观约束）。

#### A. Requirement Coherence（要求一致性）

检查当前要求集合是否明确、相互兼容、能够同时成立。

如果多个要求在逻辑或现实条件下无法同时满足，问题属于要求集合本身，而不是执行失败。

#### B. Design Adequacy（设计适当性）

检查：

> **即使各组成部分都完全按当前设计正常存在、正常工作，这套设计本身是否足以支撑当前需求？**

边界：

- Integrity（完整性）问“实际有没有偏离设计”；
- Design Adequacy（设计适当性）问“即使完全没有偏离，这个设计本身行不行”。

设计适当性必须相对于需求判断。需求或使用条件改变后，原先合理的设计可以变得不再适当。

#### C. Inherent Trade-off（固有权衡）

废弃“有得必有失”或“性能越高代价必然越大”的绝对表述。

定义：

> **在当前结构、规则或机制不变的前提下，两个或多个评价维度之间存在稳定的条件性 Coupling（耦合），使它们不能被完全独立优化，一个维度的推进会限制、牵动或压缩另一维度的可优化空间。**

“固有”只相对于当前结构成立，不代表永久自然定律。技术、结构、规则或机制改变后，原有权衡边界可以移动或被削弱。

机械审查四项：

1. **Dimensions（评价维度）**：是否存在两个或更多同时关注的指标；
2. **Coupling（耦合）**：在当前结构下，一个维度变化是否稳定影响另一个维度的可行范围；
3. **Boundary（边界）**：当前目标组合是否接近、触碰或超过这种耦合形成的可行边界；
4. **Structural Escape（结构逃逸）**：若希望多个维度同时明显改善，是否需要改变结构、机制或规则，而不是继续在现结构内微调。

Requirement Coherence 与 Inherent Trade-off 的区别：前者看要求本身能否同时成立；后者允许要求逻辑上都成立，但当前结构无法让各维度同时达到目标水平。

### 11 激励、适应与选择

适应不等于恶意。

### 12 随机实现与不可约变异

**状态：待重构。**

当前旧版方向：检查是否不存在可识别错误，只是概率风险被实现，包括正常随机波动、低概率风险实现、个体差异、不可约随机性。

必须区分：

- **Aleatory Uncertainty（随机不确定性）**：世界本身具有概率性；
- **Epistemic Uncertainty（认知不确定性）**：只是我们不知道。

本域最终是否应转化为概率属性轴，仍待审查。

## 5. 五组候选标签

搜索域负责生成探索方向。只有当方向被提升为较具体的候选因素时，再用独立字段描述，而不是逼它抢一个唯一“大类身份证”。

### A. Causal Role（因果角色）

触发；脆弱性／前置条件；传播／放大；预防屏障失败；检测失败；隔离失败；恢复失败；贡献因素等。

### B. System Locus（所在层级）

边界输入；部件／个体；接口／网络；流程／控制；团队／组织／制度／市场；外部环境；跨层系统等。

### C. Lifecycle Origin（生命周期来源）

目标／需求；设计；实现／制造／采购；部署／运行；维护／变更／迁移；退役／恢复等。

### D. Agency and Intent（能动性与意图）

无主体自然过程；无意错误；已知风险未处置；合法策略适应；规则博弈／违规；欺骗／舞弊；敌对攻击／破坏；未知。

### E. Evidential Status（证据状态）

可按具体候选使用：POSSIBLE（可能）、SUPPORTED（已有支持）、CONTRADICTED（与当前事实冲突）、EXCLUDED（已有足够证据排除）等。证据状态与域级 NORMAL / ABNORMAL / UNKNOWN / N/A 分层记录。

## 6. 开放出口

### Taxonomy Gap（分类体系缺口）

已经发现明确值得探索的方向或候选因素，但现有搜索域无法合理容纳时，必须保留自由文本并进入后续分类体系修订。

### Cause Unresolved（原因未决）

当前尚不能识别具体原因时，应继续区分：

- 尚未调查；
- 关键证据缺失；
- 多个竞争假设无法区分；
- 个案归因不可判定。

“我不知道该选 02 还是 07”不是原因未知，那是分类边界有歧义。

## 7. 压力测试规则

当前核心验证问题改为：

> **面对一个陌生问题，如果依次扫过这些方向，能不能比较高概率地发现下一步值得探索的地方？**

每个搜索域至少继续检查：

1. 它能否产生其他域不会稳定产生的探索方向；
2. 它与相邻域的边界是否足够机械化；
3. 区分该域后，是否可能导致不同的后续验证方式或下一动作；
4. 是否能跨生物、机械、软件、财务、人际、组织等问题工作；
5. 不适用时能否干净返回 N/A，而不是强迫所有问题经过每个域。

两个域同时命中不自动意味着应该合并。如果它们描述的是问题链上两个对后续探索有意义的不同位置，可以独立保留。
