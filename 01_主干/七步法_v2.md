# 七步法 v2.0（正式版）

> 状态：现行。本文件为对外交付措辞（Formal Register）；内部运行版见本地 `七步法骨架_v1.0.md`。
> 两版条款同源，措辞不同；冲突时以内部运行版为准。

---

## 摘要

七步法（Seven-Step Method, SSM）是一套通用决策流程（General Decision Procedure）。
其功能是把一个信息不完备、目标未收敛的问题，转换为一个可执行、可复核、可退出的决定。

输入：一个问题陈述（Problem Statement）。
输出：一个决定（Decision），附带代价核算（Cost Accounting）、证据（Evidence）与出口（Exit）。

七步法不预测未来，不代替使用者进行价值判断，不保证结果正确。
它保证的是：**在未完成代价核算之前，不进入实施。**

---

## 1. 定位与适用范围

### 1.1 适用

- 信息不完备（Incomplete Information）；
- 目标未收敛（Unconverged Objective）；
- 多目标冲突（Conflicting Objectives）；
- 需要留痕以备复盘的决定。

### 1.2 不适用

- 已进入执行阶段的工程动作；
- 纯查询（Pure Query）；
- 可逆、目标已定的小规模判断——此类情形依常识处理，套用流程反而增加成本。

### 1.3 与相邻层的关系

```
七步法（决策层）
    ↓
工作流程标准（执行层）
    ↓
本机规矩（环境层）
```

决策层回答「该不该做、往哪做、做到哪停」；
执行层回答「动手时按什么规矩」；
环境层回答「在这台机器上哪些做法会立刻出错」。

---

## 2. 形式化定义

设问题 P，七步法将其映射为决定 D：

```
SSM: P → (O, F, S, A, N, E, X)
```

| 符号 | 名称 | 含义 |
|---|---|---|
| O | 定界（Delimitation） | 目标状态 + 交换意愿 |
| F | 事实采样（Fact Sampling） | 事实 / 推断 / 判断 / 未知 |
| S | 结构化（Structuring） | 工具 / 外部限制 / 历史轨迹 |
| A | 归因（Attribution） | 候选方向集合 |
| N | 下一动作（Next Action） | 选定动作 + 五项核算 |
| E | 反馈（Feedback） | 实际结果 + 证据层级 |
| X | 退出（Exit / Escalation） | 六选一出口 |

约束：该映射以「决定」（Decision）为单位，不以「动作」（Action）为单位。

## 3. 七步

### 3.1 定界（Delimitation）

**问题**：要把问题推进到什么状态；愿意以什么作为交换。

**输出**：

- 目标状态（Target State）：澄清 / 裁定 / 完成 / 止损，四者择一或组合。
- 交换意愿（Willingness to Exchange）：时间、资金、体力、关系、机会、风险。

**判据**：

1. 目标状态必须可验收（Verifiable）。
2. 交换意愿不作等价性要求，亦允许为零。
3. 本步不进行可行性、成本、风险、权限判断。

**边界说明**：定界不审判欲望，亦不阻止任何行为。阻止发生在第 3.3 节「外部限制」。交换意愿是报价（Offer），不是成交（Settlement）。

---

### 3.2 事实采样（Fact Sampling）

**问题**：当前实际掌握了什么。

**输出**：四列记录。

| 列 | 定义 | 判据 |
|---|---|---|
| 事实（Fact） | 可观察、可复核、不带评价的观察 | 第三方以同等条件可复现该观察 |
| 推断（Inference） | 由事实导出、可能为假的结论 | 必须带推断标记 |
| 判断（Judgment） | 带立场的评价 | 不得混入推断 |
| 未知（Unknown） | 未掌握、未核实、不可得 | 必须独立列出 |

**判据**：

1. 推断不得书写为事实。
2. 判断不得混入推断。
3. 未知在后续步骤中不得被静默转写为已知。

**信息溯源（Information Provenance）**与**输入来源（Input Source）**须分开记录：前者回答「我如何得知」，后者回答「该对象从何处来」。

---

### 3.3 结构化（Structuring）

**问题**：当前具备什么条件，受到什么约束，来路如何。

**输出**：三个默认维度 + 两个选配维度。

#### 默认维度

| 维度 | 内容 |
|---|---|
| **工具（Instruments）** | 设备、软件、人力、资金、时间、信息、权限 |
| **外部限制（External Constraints）** | 他者（The Other）：物理规则、法律、经济、他人、时间、身体 |
| **历史轨迹（Trajectory）** | 该对象如何演化为当前状态 |

**外部限制的定义要点**：它描述「世界会如何回应」，而非「主体不应如何」。
主观交换意愿能否成立，由本维度裁定。物理规则与法律同属外部限制，二者在效力上无差别。

#### 选配维度

| 维度 | 使用场景 |
|---|---|
| **状态（State）** | 需要精确描述当前形态时 |
| **条件（Conditions）** | 诊断类问题：何种条件下现象出现、消失、增强、减弱 |

**判据**：工具与外部限制必须分列。合并书写将导致「能力」被误读为「许可」。

---

### 3.4 归因（Attribution）

**问题**：存在哪些值得继续探索的方向。

**输出**：候选方向集合（Candidate Set），基数 2–5。

**判据**：

1. 不输出唯一根因（Single Root Cause）。
2. 不输出解决方案（Solution）。
3. 不输出行动授权（Authorization）。
4. 每个搜索域（Search Domain）先写判据，再返回四值之一。

**域级四值（Domain Status）**：

| 值 | 含义 |
|---|---|
| 是（Yes） | 存在值得继续探索的偏离或命中 |
| 否（No） | 按当前判据未命中，不等于已排除 |
| 未知（Unknown） | 信息不足或判据未建立 |
| 不适用（N/A） | 对该问题无意义 |

**候选证据状态（Evidential Status）**独立记录，不与域级四值混层：

| 值 | 含义 |
|---|---|
| POSSIBLE | 可能 |
| SUPPORTED | 已有支持 |
| CONTRADICTED | 与现有事实冲突 |
| EXCLUDED | 已排除 |

**搜索域**：01–07 为可用域；08–12 已搁置（PARKED），不参与候选生成。

**排序**：先按可解释事实数量，再按可验证性。

---

### 3.5 下一动作与执行（Next Action & Execution）

**问题**：选择哪一条路径，如何排序，如何实施。

**输出**：一个动作（Action）及其核算（Accounting）。

**五项核算**：

| 项 | 问题 |
|---|---|
| 结果（Result） | 该动作能将目标推进至何种程度 |
| 成本（Cost） | 预计并主动接受的付出 |
| 风险（Risk） | 除成本外可能发生的额外损失 |
| 信息（Information） | 即使未解决问题，是否提升后续判断能力 |
| 余地（Slack） | 执行后剩余的未来行动空间 |

**判据**：五项构成帕累托关系（Pareto Relation）。不要求全部改善，只排除被全面压制（Dominated）的选项。
当一项得分显著提高而「余地」降至零时，属于高风险选择，须显式标注。

**施工四道门（Four Gates）**：

| 门 | 产出 | 不过的表现 |
|---|---|---|
| 目标门（Objective） | 可验收的完成定义 | 「先做起来看看」 |
| 路线门（Route） | 主路线 + 被否决的备选及理由 | 只有一条路 |
| 工具门（Instruments） | 工具清单，含路径与版本 | 「到时候再装」 |
| 施工门（Execution） | 前三门文档落盘 | 边干边补文档 |

前三门未过，不得进入第四门。

**前置审结（Pre-Review）**：

1. 该问题是否适合交由本流程处理；
2. 应调用完整流程还是单一工具；
3. 是否存在必须先补齐的信息或权限；
4. 当前允许的动作级别为何。

---

### 3.6 反馈（Feedback）

**问题**：实际发生了什么。

**输出**：三行记录 + 证据层级标注。

1. 实际执行了什么（非计划）；
2. 实际发生了什么（附证据）；
3. 判断因此发生何种改变。

**取证四层（Evidence Layers）**，由弱至强：

| 层 | 形式 | 强度 |
|---|---|---|
| 1 | 直接观察（Direct Observation） | 最弱，易受预期影响 |
| 2 | 留痕（Artifact） | 文件、哈希、日志、截图、录音 |
| 3 | 第三方确认（Third-Party Confirmation） | 回执、ID、签收、复述 |
| 4 | 复现（Reproduction） | 最强，重做结果一致 |

**判据**：能上移一层则上移一层。仅达第 1 层者，须显式标注。

**两个诚实边界**：

- 不可复现之事（一次性决定、不可逆动作）：须在实施前完成留痕。
- 无第三方之事（私人感受、审美判断）：上限为第 2 层，须标注「仅本人可证」。

**反例**：退出码 0、日志中的 ok、调度器报成功，均属自述性留痕（Self-Reported Artifact），不等于取证。

---

### 3.7 退出与升级（Exit / Escalation）

**问题**：下一步做什么。

**输出**：六选一，必须显式书写，不得留空。

| 出口 | 判据 |
|---|---|
| 继续（Continue） | 未知不跨界，且尚有推进空间 |
| 等待（Wait） | 未知跨界，但等待可产生信息增量且成本可接受 |
| 换路（Reroute） | 当前路径不通，存在替代路径 |
| 停止（Stop） | 目标已不值得，或边际成本超过边际收益 |
| 升级（Escalate） | 关键未知只能由外部主体消除 |
| 重新定界（Redelimit） | 目标本身有误，须返回 3.1 |

**判定顺序**：目标是否成立 → 信息是否充分 → 是否存在替代路径 → 是否具备自主执行条件 → 方才判定「继续」。

**升级摘要（Escalation Brief）**：

> 我要达到 ______。现在确认 ______。已经试过 ______，结果是 ______。目前主要候选是 ______。但因为 ______，我卡在这里。我需要对方帮助 ______。当前约束是 ______。

**后置审结（Post-Review）**：

风险是否可承受；后果是否可逆；权限是否足够；关键未知是否跨越执行边界；是否须等待主体恢复后重判。

无法判断时，不创建无限元审计器（Meta-Auditor），默认为：暂不自动实施，退回主体。

## 4. 使用规则

### 4.1 粒度（Granularity）

以「决定」为单位，不以「动作」为单位。
一个决定可产出一组动作，该组动作不重复运行流程。
重跑条件仅两条：第 3.6 节改变判断，或第 3.7 节选择「重新定界」。

### 4.2 分级（Tiering）

| 级别 | 判据 | 执行范围 |
|---|---|---|
| 小决定 | 可逆、不涉存续、目标已定 | 3.1、3.2、3.5、3.7 |
| 大决定 | 不可逆，或涉资金、对外、账号、数据删除、身体 | 七步全流程 |
| 动作 | 属于某一决定的执行细节 | 不单独运行 |

### 4.3 硬边界（Hard Boundaries）

1. **UNKNOWN 是合法输出。**「处理不了」不构成流程失败。
2. **禁止无依据补全。** 禁止将 UNKNOWN 在中间步骤转写为已知。
3. **禁止以模糊词判定异常。** 无明确判据时，只能返回「未知」或「不适用」。
4. **流程完成不等于取得执行权。** 高风险、不可逆、关键未知跨界时，退回主体。
   反之，错误后果处于预先授权、可逆、可承担范围内的，可授予有限代理（Limited Agency）。低风险不等于无授权。
5. **三种可靠性不得互相替代**：复现可靠性（Reproduction Reliability）、决策可靠性（Decision Reliability）、安全可靠性（Safety Reliability）。
6. **主体与方法共享盲点（Shared Blind Spot）。** 事后同意仅增强复现可靠性，不证明现实正确。

## 7. 常见误用

1. 将流程当作演示（Performing the Process）——可逆小事的常识判断无须运行。
2. 跳过结构化直接选路——未核算外部限制的路径不成立。
3. 退出步骤留空——不写等同于默认「继续」。
4. 将定界报价视为已成交——报价是主观的，成交由外部限制裁定。
5. 归因阶段只保留一条路径——说明未完成收敛。
6. 以「结果」单项最高分选动作——将导致余地归零，一次耗尽退路。
